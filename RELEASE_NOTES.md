# VGRPresenter 0.0.7

## What's new

- Scripture's and The Table's search boxes have a lock beside the exact-words padlock. Switch it on and the search stays inside what you are reading — the Bible chapter on screen, or the sermon you have open — instead of searching the whole library. The box says what it is searching (for example, "Search in Revelation 1") and the lock follows you as you move to another chapter. It is offered on the two tabs that hold books; the app-wide search still looks everywhere.
- Exact word search is available across sermons, Scripture, shows, slides, templates, overlays, categories, settings, media and songs.
- A style can allow or hide the live overlays on each output independently.
- Audio & Video settings show levels from VGRPresenter's own program mix.
- A media file or an NDI stream now plays its own audio through the app: its level is shown on its card and in its Edit dialog, it is mixed into every bus it is routed to, and it is heard on the program output.

## Improvements

- A file that is not a sermon is turned away by name instead of imported as garbled text. "New sermon" and "Add sermons folder" both promise a .txt or a .pdf, but a file can still arrive from a typed path, a drag or an "All files" filter, and a Word document, an image or a spreadsheet with the wrong name reaching the text reader used to import "successfully" as pages of noise. Every import is now checked before it is read: the name must end in .txt or .pdf, and a file whose own first bytes say it is something else is refused whatever it is called. A PDF saved as .txt is told to be renamed .pdf. Only the file's format is judged, never its content, so a real text file with odd characters is still read and tidied as before.
- "Add sermons folder" says what it took and what it would not take. It used to count only sermons, so a folder of 40 sermons beside 300 spreadsheets answered "40 imported" and said nothing about the rest. It now lists every refused file by name with the reason ("Skipped notes.docx: not a sermon file") beside the imported, already-there and failed counts, files that were never sermon formats are not counted as failures, and there is no "and 3 more" — every skipped file gets its own line so you can see what to fix.
- A laptop's battery says which of its three states it is in. There were only two — "On battery" and "Plugged in" — so a machine that was topping up looked exactly like one sitting full, and the Smart Config battery dial could not say that charge was going up. It now reads "Charging · 30%" on the row and "Battery · charging" on the dial, while a pack that is plugged in and holding still still reads "Plugged in".
- The language choice says what it did. Every other Appearance choice is visible immediately, while picking a language moved half of itself invisibly: dates, times and numbers follow it at once, and the words of the interface need a translation file this build does not carry yet, so the interface stays English. A notice now says exactly that instead of leaving you to guess whether the app ignored you.
- The small print on Settings is readable. The line under a setting that explains what it does was drawn at the smallest size in the app — the size meant for badges and unit suffixes — so the one sentence that says what a switch actually does read as a footnote. Those explanations, and a dial's caption under its value, are now a comfortably readable step below the setting's own label, on Settings · General, Settings · Smart Config and every form caption. Badges and chips are unchanged.
- "Resume last session" is a deliberate choice, not the default. A fresh install starts on the home (Show) screen with nothing opened, whatever the last session was doing; coming back to the show, the design and the Settings page you left is opt-in.
- Crash recovery is an offer now, not a takeover. After an unexpected exit the app starts where you asked it to — the home screen — and a notice names the show that is waiting, in bold, with one button that opens it. It used to open the recovered copy on the Edit screen by itself, before the launch had even settled, with only a toast you had already missed to explain why. Nothing is opened or switched until you click, the recovered copy is written as a new show only when you take the offer, and an offer you have not answered survives a later clean exit, so the work is still there next launch.
- The last word you type is matched while you are still typing it, everywhere search runs. A half-typed word is no longer guessed into one word ("compelling that you rec" used to become "received", which lost the sermon that says "receive"): it matches every word that starts with what you have typed, the more common readings first, and every earlier word still has to be there. The hint names the readings ("rec → receive · received · record") while the word is still open.
- App-wide search results show a match rating on every row ("MATCH 100%") — how much of what you typed the row itself carries — and the rows are ordered by it, so a row's place in the list is readable instead of taken on trust.
- Search puts exact phrases and nearby words ahead of scattered matches, and sermon search builds word summaries in the background so sermons that cannot match are skipped.
- Sermon search is several times faster on a large library: on 1,200 sermons a four-word locked search went from about 14 seconds to about 0.8, a three-word one from about 4.4 seconds to about 1.1, and a single common word from about 0.5 seconds to about 0.08.
- Search results show the sermon text that matched and open on its continuation when a passage is split; Bible results use the full verse text for matching and ranking.
- Search and chapter reading run in the background, so the interface stays responsive while results or text load, and the search box waits for a pause in typing — one search per phrase instead of one per keystroke, so the results on screen belong to what you typed.
- The app and its dialogs scale to the display. The editor and the Audio & Video routing board adapt to narrower windows, and the column widths you set are remembered.
- Output previews use a compact, paginated grid, and the resolutions you configure size both the rendered frames and the HDMI windows.
- NDI sending runs off the interface thread with warm-up and frame-rate status, and preview connections recover after NDI is turned off and on again.
- More automatic checks guard the app: exact search, moving between results, dialog fit, window resizing, remembered column widths and the Media pane's bus status light. The Table's result rows have one that types into the search box and counts the highlight pixels actually painted — a highlight nobody can see does not count, whatever the code says.
- Metadata is a menu now, not a spelling test. The Edit screen's + menu has a Metadata pill listing every placeholder the engine fills — text, number, reference, verses, book, book abbreviation, chapter, version, copyright and The Table's code — grouped, with each chip showing its name over the token. Click one to add a text item carrying it, or drag it onto the canvas to drop it where the pointer is.
- A The Table template can show a sermon's date code on its own. Where the old placeholder wrote the whole citation line ("47-0412 - Faith Is The Substance"), the new one writes only the code ("47-0412"). It is blank for Scripture — a verse has no date code — and a template whose only placeholder is the code is still recognised as one the engine fills.
- A typed The Table handle is read the same however its dash is spaced: "47-1020", "47 - 1020" and "47- 1020" all name the same sermon, both in the box that jumps to it and in the list. Only the spaces beside a dash are ignored, so a title's own spaces still have to match.
- The app's cursors are measured rather than assumed: a script parks the real pointer on a control and on the window's own frame and reads the shape the system is actually showing, at the design size and with the window 20% larger.
- A channel's state can be read in words, not only in colours. Hovering an L/R button or a channel's gain knob says what that channel is doing — "Off", "Trimmed -6.0 dB", "Unity · 0 dB" — including how far a side is trimmed, because "Trimmed" alone never said by how much. The same side reads the same way on an input card, a bus card and a video card, the tip appears after a moment, follows the control if it moves, and goes when the pointer leaves.
- The metadata palette reads as a panel instead of a grid of tokens: each group has its own heading, the panel says that a field can be clicked or dragged, the chip under the pointer is ticked down its edge, and the line explaining a field sits in a fixed spot — it can no longer grow the panel upward under the pointer, which is what made hovering flicker.
- The unit test suite can be run one phase at a time with a timeout, so a test that gets stuck names the phase it stuck in instead of hiding every result after it.
- The app's reds mean one of two things, and each now has a single home: a fault (an error, a delete button, a failed step, a nearly full disk) and a LIVE state (recording, a running flow, an on-air output, the GO LIVE pill). Ten files were spelling those same reds by hand in nine slightly different shades, so a live output and a failed step could look like the same kind of red while meaning different things. Surface tints and content colours keep their own values on purpose.
- Booting asks the system only for the hardware this setup names: the audio devices the input list uses and the cameras the video list uses are looked for, and no other device is activated or camera opened. Add or Edit in Audio & Video still lists the whole machine, which is where a new device is chosen.
- "Max words per slide" is the whole rule for where a long verse or paragraph is divided, and the settings that used to overrule it are gone. It was the smallest of three numbers — yours, a "Tolerance" percent, and the template's own text box, estimated in characters and divided by six — and only the last one was invisible; it is what made a sermon paragraph come out as four-word slides while the setting on screen said forty. A long passage is now divided into the fewest parts the budget allows, holding as close to the same number of words as they can: a 43-word paragraph at a 40-word setting is two parts of 22 and 21, never 40 + 3, and the budget is never exceeded. "Number the parts (1a, 1b)", "Tolerance", "Paragraphs on individual lines" and "Smart split" went with it.
- A bus card in Media · Inputs shows its connection state as a light that keeps itself right: green while a source is routed into the bus and that source is still there, amber while the routing is there but its device is not available right now (a closed window, an unplugged camera), red while nothing is routed into it. Two things used to keep it amber while every device was present — the card was never told when the answer changed, and the startup scan only looks at the devices this setup names — and both are fixed: the light follows the app's own device announcements, and it asks for the device it is about by name, off the interface thread, without opening anything. The light also means DELIVERING now, not merely present: while the app is already pulling from a source, one that has gone quiet shows amber ("source is not delivering") instead of green, and a still picture counts as delivering. Nothing is opened to answer that — a source nobody is watching keeps its normal answer rather than being painted amber for not being looked at. The middle of the window is now for the bus's picture and its live L/R pair, with the name and its routing line below and the light in the corner, and the L/R pair still lights on that bus's own live mix once its monitor is opened. The bus monitor's own picture could also stay empty for a whole preview, which is fixed here too, and the automatic check now holds both a video and an audio source for real and confirms the card agrees with what that source is actually sending.
- The ‹ › arrows at the reference preview walk the picked passage part by part before moving on. A long sermon paragraph is already offered as its own parts in the list (4, 4-2, 4-3), but an arrow used to jump straight from 4 to the following paragraph and never showed the rest of the passage it had picked. › now shows 4-2 and then 4-3 — the same parts the list offers as rows — and only the step past the last part moves to the next paragraph; ‹ does the same in reverse. Stepping into a passage lands where you came from: forward opens the next passage at its first part, and back opens the previous one at its last part. Each step puts that one part on the preview and on the output, so the picture and the list agree on which part is up, and stepping while some other passage is on air moves only what you are looking at rather than taking the output over.

## Fixes

- A keyable output is see-through on the real screen, not only on the tile. A frame the app deliberately leaves unpainted is transparent all the way out; the output window no longer paints plain black behind it, so an operator keying or recording behind the app gets the transparency they set up instead of a black rectangle. (The checkerboard that shows transparency on purpose is still available.)
- Media and background pictures are crisp on the outputs instead of blocky or shimmering. A picture the app has to resize — a smaller video playing into a bigger output, a large photo fitted onto the stage — used to be scaled by picking the nearest pixel, which looked blocky when it was enlarged and shimmered when it was reduced. It is now scaled smoothly, the same in the preview and on the outputs.
- Going live with nothing but a camera, a screen or a media file on the air shows that picture instead of black. A design's own background now sits under the live picture while its decorations and text stay over it, so a template can frame a live feed but never bury it, and the app's log says which layers each scene was built from. Which paint counts as a background is a choice, not a rule: a design (or a single part of one) can say whether it belongs under or over the feed.
- The Resource profile card's own description no longer runs under its controls. The sentence explaining the choice, the Performance/Balanced/Power Saver picks and the "Manage" link now sit in rows, and the card grows with its text instead of the text running straight through the controls.
- A media source's level bar on the Audio & Video board reads its sound, not its Volume setting. It drew the saved volume — a fill that tracked the Volume slider and never moved — so the card showed a level while the same row's Edit dialog showed silence. Both surfaces now read the live audio, and a row whose file is gone, or which is simply silent, rests at zero on both.
- The interface no longer freezes when a media source's audio reaches the end of its file. The thread that decodes the file held on to the level meter's lock while waiting after the file had played out, so the app's own meter update — which needs that lock, on the interface thread — waited on it forever and everything stopped until the app was killed. The wait now happens with the lock released.
- Search no longer lists results that are missing a word you typed. "compelling that you recieve" answered with verses that only say "you that", while the sermon that says "compelling and compulsory, that you receive" was not at the top. Every typed word must now appear in a result, with only the last one allowed to be half typed, so the sermon carrying all of them leads and the partial rows are gone.
- The Table's result rows highlight every word you typed. A row used to show one word in the match colour and the others plain grey, because only the app's spelling corrections were highlighted; the words you typed are always highlighted now.
- The matched words in The Table's result rows sit in the middle of the row instead of past its right edge. Rows are one line tall while the excerpt can be long, so a match far into it was simply off screen; the excerpt is now shown around the group of typed words that sits closest together.
- The Table's own search box offers the spelling correction while results are on screen. The correction ("compeling → compelling") and the readings of a half-typed word used to appear only when nothing was found — the case where they help least.
- Search excerpts now centre on the nearby group of words that matched, instead of on an unrelated earlier appearance of a common word.
- Live camera, screen, media and overlay content refreshes while it is on air, and cached scenes update when a template's styling changes.
- NDI start, stop, re-enable and shutdown are fixed, and sending follows the rate and resolution you configured.
- Selecting The Table content while live queues the change in the background, so several outputs no longer block the interface.
- Result rows no longer re-evaluate on every frame (a row measured its excerpt inside the same expression that wrote the measurement, which the framework reported as a repeated loop).
- The program meter reads VGRPresenter's own mix rather than capturing the system's audio.
- Clearing audio from the monitor no longer stops the level meters owned by Media; Settings and Media keep showing the same live levels.
- Dialogs stay inside the app window, dim the whole app and show their dropdowns above other dialogs; blank or clipped dialog content and a crash when choosing from a dropdown are fixed.
- Opening Audio & Video and its source dialogs uses the hardware list the app already has, and finding and opening a camera now happens off the interface thread.
- Saved settings keep your workspace widths, per-category show templates, song templates and output overlay styles.
- Repeated window resizing is fixed, and output preview sizing and live-state reporting are corrected.
- Starting, stopping or rotating a recording no longer stalls the rest of the app: the recording engine opens and closes its file outside its own lock, so other parts keep running while a recording starts or ends.
- Automation steps, cues and event-triggered flows no longer hold the automation engine's lock, so a step that waits on a device no longer pauses other engines.
- Editing the production layout saves once per change instead of on every intermediate value, and saves outside the production engine's lock, so dragging a fader no longer writes to disk at every step.
- The build now fails if a lock is held across a slow hardware, disk or cross-engine call, with a documented one-line waiver for the in-memory cases that are safe. The same check runs as a test of its own, so a violation is reported as a failing test.
- That check now also fails on a lock held across an event dispatch, a stored callback or another engine's notification, since a subscriber's code runs inside the lock exactly like a device call would. The roughly 50 places that already did this are recorded in a checked-in list, so only newly introduced ones fail the build and the list can shrink as each is fixed.
- The same check now covers the system layer too, where the waits belong to Windows: waiting on a device, sleeping, reading from a device, a network call or waiting for the window compositor. One case is handled deliberately — a condition variable's wait releases the lock it is given, so it is only reported when another lock is also held.
- The check now reports a waiver that has gone stale — the line it sits on no longer has anything to waive — instead of counting it as reviewed.
- A damaged settings database no longer stops the app from starting. The unreadable file is set aside beside the original as evidence and a fresh one is written in its place, so settings keep saving in the same session.
- Every other file the app keeps for itself recovers the same way: settings, the engine configuration, the project and design libraries, the media library and its stored index, The Table and Bible stores and the crash-recovery note are all set aside as evidence and rebuilt from defaults instead of failing the read, so one damaged file can no longer take a screen or a launch down with it. A file that still reads but has lost the section the app writes counts as damaged too, so it is preserved rather than read as empty and overwritten by the next save.
- Saving verifies what it wrote. An atomic save now compares the file against the bytes it wrote, pushes the data to the disk before swapping the file into place, and flushes the folder afterwards, so a power cut cannot publish a new file whose contents are still only in the drive's cache.
- Every file the app saves for itself — settings, templates, overlays, projects, the project library, backups, the media and design libraries, The Table and Bible stores, notification history, thumbnails and crash-recovery notes — is written to a temporary file and swapped in, so an interrupted save cannot leave a half-written file behind. It is one shared implementation instead of one per saver.
- Restoring a backup over a live settings file no longer deletes the live file first, so a restore that fails leaves the previous file in place.
- Exact-word search with the lock on matches only the typed words as they appear together: a page that holds them apart is no longer returned, while a shorter combination the text really contains still answers.
- Buses and the rest of the production routing are saved as you edit them, not only when the app closes. A crash, a forced quit or a killed task used to lose every bus built in that session; edits now land within a second, and the engine's own final save runs before the database is written at shutdown.
- STOP now only stops the outgoing picture. It used to blank the slide out of the monitor preview as it went off air, so pressing the button threw the tile back to the empty checkerboard and your pick was gone — pressing GO LIVE again then sent a blank holding screen instead of the content. Going off air now hands the pick back to the preview, so the monitor keeps the picture it had, GO LIVE puts that same content back out, and Clear all still clears it.
- The ‹ › buttons step what you picked whether it is on air or only being previewed. A verse or paragraph you double-click is placed on the Main Output tile as a preview until you press GO LIVE, and the wall's arrows were greyed out in exactly that state, because nothing was "on air" yet — so they did nothing at all, while the preview pane's own arrows moved the list and left the output on the previous passage. A previewed pick is now stepped like an on-air one, so both pairs come to life and the step always reaches the tab that owns the pick — the wall's buttons work on the Edit screen as well as the Show screen, instead of needing that tab to be the one on screen.
- The monitor tiles fill the whole output column now. The wall was capped at a fixed width and centred, so on any wider column the tiles stopped short and sat in a band of empty background; it now runs edge to edge, so the tiles meet both ends and each other with nothing in between. The Edit screen's ITEMS tab keeps its own rail, aligned with the labels beside it.
- The monitor wall no longer reads as on-air because a meter is running somewhere else in the app. Setting up an audio row in Settings meters its device so its strips move, and that used to light the wall's audio button and animate the preview meters — with nothing taken, nothing live and nothing Clear all could release. A meter is an observation, not content: the wall reports only what the wall is doing, and the preview's input meters move while the output is on air.
- The audio and video source dialogs are one design now — Edit Audio Input, Edit Video Source and the Add Source dialog's two tabs: the same label rail, the same Kind row and the same Name/Source/Volume/Channels fields, with the sections a camera or screen has no use for simply hidden, and the video preview as the one section audio has no counterpart for.
- A device the app was remembered with that is not attached this time is announced once, right after the startup report, instead of leaving a source that meters nothing or previews black.
- The startup report now says which devices this session is USING instead of counting every device on the machine, and it waits for the scan that knows what the app asked for — which is what made it read "0 audio devices" on a machine full of them.
- A notice points at its subject instead of making you read to find it. The names a notice is about — the hardware in use, the device that came back missing, the source a sentence mentions — are drawn in bold inside the message, so your eye lands on "Microphone (Realtek(R) Audio)" in a five-second toast instead of scanning grey text. The app also bolds a name that is already written in quotes, which is how most of its sentences name a project, a category or a search query, and the bold never changes a character of the text.
- The metadata palette is lifted above the edit canvas. It was drawn at the same level as the canvas, so the text item underneath still owned the pointer: an I-beam cursor showed through the open panel and its chips showed a plain arrow. The open panel now owns the pointer, so the item beneath it reads as blocked while each chip shows a pointing hand.
- A click anywhere outside the metadata palette closes it. It used to close only on a click on empty canvas, so clicking the toolbar, the slide list, a panel or an object left it standing. A press anywhere else on the screen now dismisses it, and scrolling outside it closes it too.
- Closing the app (or the test suite) after previewing a camera or a screen no longer hangs when a capture is stuck inside its driver. Camera previews read frames asynchronously and cancel the pending read on shutdown, so the preview always exits; a screen or window capture, which cannot be cancelled at all, is given a bound and abandoned only when the window is genuinely wedged.
- Every L/R button in the Media pane's Inputs cards now closes only its own side, and all three card kinds — audio input, bus and video source — use the one shared control instead of three drifting copies. Clicking L used to close more than L: a bus card muted the whole bus, and a video card's two buttons both wrote the same mute flag, so one click darkened both sides with no way to close just one. Each button now writes its own side's trim, the same value the mixer reads, and a video row keeps that trim with the rest of its saved setup.
- Closing a side from a Media pane button and reopening it gives back the level it was closed at. Every button reopened its side at full level, so a side trimmed to -6 dB came back at 0 dB. The trim now lives with the row and is saved like its gains, so it survives a restart, and a side with no remembered trim still comes back at full level rather than at the zero that "closed" is stored as.
- The Edit Video Source dialog's channel knobs do something now. They moved nothing at all: a media or NDI row's per-side trims and channel on/off boxes were never connected to the row, so the same row could be trimmed and closed from its Media card but not from its own dialog, and dragging a knob there wrote to nothing. The dialog now reads and writes the same state the card's L/R buttons do, including the trim a closed side comes back at.
- Picking a style background image no longer risks taking the app down: the file picker is opened after the click handler has returned, so switching settings sections while it is open can no longer destroy the control mid-callback.
- The monitor preview tile now shows what the output shows. A pushed camera or media frame is no longer buried under the transparency checkerboard when a style's background is transparent (the checkerboard now sits underneath the content, so it can only show where nothing paints), and the tile is composed from the style the Styles screen is editing instead of a copy read at startup, which kept previewing the previous template and background after a style was changed.
- The Edit canvas keeps its adjustment points where they can be grabbed. A text item framed to the canvas edge put half of every resize point, and its whole edge strip, outside the clipped canvas, so there was nothing to hover and no size cursor to show. The handles are now held inside the canvas edge, and each shows its own size arrow instead of alternating with the text cursor.
- A drag on the canvas ends its grab cursor when you release the button. The closed hand used to stay on screen, because the shape was tied to a flag that stays set for the rest of the gesture; the grab is now a live-press state.
- The app's own window frame shows the resize cursor. Hovering the border of the frameless window showed a plain arrow, with the size arrow appearing only as a flash while the pointer moved. The sides now show the horizontal arrow and the corners the matching diagonal, steadily, while the pointing hand on ordinary controls is unchanged.
- A one-word search with Exact words on finds the sermons that contain the word again. The shortcut that skipped a step a single word never needed also skipped the match itself, so a locked one-word search in The Table answered with nothing at all.
- A video source's own audio is real audio now. Its card's L/R buttons and its Edit dialog's channel strips used to show the row's saved Volume back at you, so the bars sat partly filled and moved with the fader instead of the sound; they now read the live audio, and a row whose source is missing reads silence.
- A bus renders audio — and its own L/R buttons light — as soon as a source is routed to it. The mixer was only fed the sources some open dialog happened to be metering, so a bus built in Settings sounded and animated only while that device was on screen elsewhere. The engine now binds and meters every source the routing names, including a video row routed into a bus, whose track the bus's audio side now sums.
- Volume, mute and the L/R trims of a video or NDI source reach the engine. They were saved but never applied, so a media row routed into a bus played at full level whatever its card said, and clicking one of its buttons changed nothing audible.
- A source card's route line goes with the card when the card is deleted. Deleting a card used to cut the route only inside the engine, so its line stayed drawn on the board and could no longer be removed at all — the line's own click needs the row that is already gone. Deleting a card now disconnects it from every bus it feeds first, while the row still exists, so the route named on screen is the route that is cut, and a connector whose row is not on the board is no longer drawn at all.
- Routing chosen in the Audio & Video routing matrix takes effect and comes back after a restart. The choices were stored and shown again, but no connection was ever made from them, so a source routed there produced no audio and no meter; a row routed on one channel now sounds only on that channel of that bus.
- A video preview that can never produce a picture now says why, instead of pulsing a connecting ring for as long as its card is on screen. Starting a preview only accepts the request — the device is opened in the background, because opening a camera can take seconds — and that opening can fail (unplugged, busy, a driver error, a monitor or window that is gone). Such a preview used to look exactly like one that was still warming up, and the device was never retried for the rest of the session. Every way a preview can fail now records the reason — "device activation failed", "window closed", "no frame could be grabbed" — the ring stops and the reason takes its place, on the Media cards and the Audio & Video rows, and a camera that comes back after being unplugged can be previewed again.
- The Media pane's bus cards put their L/R buttons in the lower-right corner of the window, the same place the video cards put theirs, so the bus's picture has the middle to itself and the two card kinds read alike.
- An output that nothing has painted yet is see-through, not a black slab. A frame with no style colour, no background image and nothing pushed used to be drawn as solid black, which read as a projector's no-signal state; now nothing named means nothing painted, so the output stays transparent until something actually fills it — a style colour, a background image, a template's own background, a design's backdrop or pushed content. The monitor tile, the output window and the NDI/HDMI frames all read the same decision, and a style that chose "transparent" is still told apart from one that names nothing.
- A style's background — its colour, its background image, a template's own backdrop, and the rule that steps an image aside for content — is now decided in exactly one place, and the preview, the outputs and the NDI feed all read that decision. Before, the engine worked it out in three separate places and they had already drifted: a preview could render a layout no output was rendering, and a blank go-live carrier lost its branded backdrop on the tile while the engine went on painting it. What goes on air is unchanged.
